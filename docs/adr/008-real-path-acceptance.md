# ADR-008：验收走真实下游，演示数据默认关闭

- **状态**：`Accepted`
- **日期**：2026-11-28
- **关联**：[ADR-007](./007-cross-agent-gateway.md)

## 背景与问题

控制台早期用种子数据、内存态和沙箱预置结果来演示模块。这让「看起来能跑」和「宿主经本网关真正调到下游」混在一起，出现过用写死的成功文案冒充 `tools/call`、或未关演示数据就做验收的情况。对跨 Agent 网关来说，不能过关的是真实进程与真实协议，而不是演示面板。

## 备选方案对比

| 方案 | 优点 | 缺点 | 结论 |
| :--- | :--- | :--- | :--- |
| **方案 A**：继续用沙箱 / 内存 / 写死结果作为验收依据 | 不依赖外部服务，演示稳定 | 无法证明网关能被真实宿主使用，容易误报完成 | 否决 |
| **方案 B**：仓库中删除全部演示数据 | 验收路径干净 | 控制台讲解与空状态演示困难，运行时也无法再打开演示 | 否决 |
| **方案 C（采用）**：演示数据可以加载，但默认关闭；展示与 MCP 暴露层过滤；验收必须走真实进程 | 演示和真链路可以切换，且默认不会污染宿主工具列表 | 测试与联调必须显式管理数据文件和开关，不能写进仓库的 `data/` | **采纳** |

## 决策与工程后果

- `TOOLBOX_DEMO_DATA` 与控制台开关默认关闭演示数据；需要时再打开，且必须明确标记。
- MCP 的 `tools/list`（以及后续暴露的 resources / prompts）不得对宿主列出演示工具。
- 验收使用真实子进程或真实远程下游，经本网关被 Codex 等宿主列出并调用；禁止用 `executeRpc` 预置场景或硬编码成功结果代替。
- `data/` 与 `data/.vault-key` 不进 git。测试必须把 `TOOLBOX_DATA_FILE`、`TOOLBOX_LOCK_FILE` 指到临时文件，避免改写仓库中的 `toolbox.lock.json`。
- fixture 用于协议级真进程联调，与演示种子数据分开，并由独立开关控制可见性。
