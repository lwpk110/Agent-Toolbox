# ADR-009：知识库先交付现有检索，暂缓向量引擎

- **状态**：`Accepted`
- **日期**：2026-11-28
- **修订**：[ADR-005](./005-local-vector-engine.md) 的落地顺序（不改变其目标架构）

## 背景与问题

[ADR-005](./005-local-vector-engine.md) 已决定目标形态是本地嵌入式向量引擎（文档 + 跨宿主记忆 + 能力路由）。若在网关主路径（真实下游、Skill 执行、同步、入口指纹锁）尚未完全走通时就引入嵌入模型与 LanceDB / SQLite-vec，会把「导入一篇文档并被宿主检索到」和「建设向量基础设施」绑在一起，延误作为跨 Agent 网关的可用性。

当前实现已有关键词与同义词检索。先用这条路径证明：关闭演示数据后，新导入的文档能被 `toolbox__search_knowledge` 命中，并在重启后仍然可检索。

## 备选方案对比

| 方案 | 优点 | 缺点 | 结论 |
| :--- | :--- | :--- | :--- |
| **方案 A**：本轮直接按 ADR-005 上向量引擎 | 一次到位，贴近目标架构 | 增加模型与索引依赖，阻塞当前真链路验收 | 否决（作为后续迭代） |
| **方案 B**：取消 ADR-005，长期只做关键词检索 | 实现简单 | 无法支撑语义路由与跨宿主记忆的目标设计 | 否决 |
| **方案 C（采用）**：当前迭代只用现有检索做真实导入与宿主验收；向量引擎延后，仍以 ADR-005 为准 | 先证明网关侧知识能力可用，再加索引 | 在向量落地前，语义召回能力有限 | **采纳** |

## 决策与工程后果

- 知识库本轮范围：导入真实 Markdown、关闭演示数据后必须命中新文档而不是种子文档、经本网关被宿主调用、结果可持久化。不在本轮引入嵌入模型或向量库。
- 规格与验收不得写成「用真正的向量检索替换关键词演示」，以免被理解为本轮要加 embeddings。
- 向量引擎启动时另开实现规格，并回写 ADR-005 的落地说明。
