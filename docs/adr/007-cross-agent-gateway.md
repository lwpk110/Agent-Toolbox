# ADR-007：核心定位为跨 Agent 的本地工具网关

- **状态**：`Accepted`
- **日期**：2026-11-28

## 背景与问题

Agent-Toolbox 同时包含控制台、Skill 中心、知识库、同步与 Vault 等模块，容易在迭代中滑向「通用 RAG 产品」「Skill 市场」或「托管多租户 MCP 云」。若不先明确核心定位，后续功能取舍、验收标准和对外集成都会发散。

本项目要解决的问题是：多名 AI Agent 宿主（Antigravity、Claude Code、Codex CLI、OpenCode，以及后续其它客户端）各自配置、各自拉起下游 MCP 时，工具入口分裂、凭证散落、上下文被工具列表撑爆，且缺少统一的完整性校验与审计。

## 备选方案对比

| 方案 | 优点 | 缺点 | 结论 |
| :--- | :--- | :--- | :--- |
| **方案 A**：做成按宿主安装的 Skill / 规则管理器 | 贴近单一编辑器的使用习惯 | 无法成为各 Agent 共用的工具入口，与 [ADR-001](./001-single-daemon.md)、[ADR-003](./003-dual-layer-skill.md) 冲突 | 否决 |
| **方案 B**：做成托管多租户 MCP 聚合云 | 开箱即用的 OAuth 与目录，运维外包 | 偏离 local-first，密钥与审计离开用户机器，也不是当前要交付的形态 | 否决（可作更远期选项，须另开 ADR） |
| **方案 C（采用）**：跨 Agent 的本地工具网关——各宿主只连一个 MCP 入口，由本网关聚合下游工具、执行安全中间件，并按需提供 Skill 与知识能力 | 与已采纳的单一守护进程、指纹锁、Vault 注入一致；新功能有明确的取舍标准 | 必须持续适配多种宿主，并克制与「网关」无关的范围膨胀 | **采纳** |

## 决策与工程后果

- Agent-Toolbox 的核心是**跨 Agent 工具网关**：本地常驻、唯一 MCP 入口、多宿主共用、多下游聚合。
- Skill 中心、知识库、GitOps 同步和 Vault 是网关的配套能力，用来让各宿主更安全、更省上下文地使用工具，而不是独立产品线。
- 此后每一项产品或架构决策都要先问：是否让这个跨 Agent 网关更完整、更安全、或更容易接入？不符合的需求不得插入当前主路径。
- 架构与产品决策必须写成 ADR，并更新本目录索引；已定决策若被修订，在原文注明日期并互相同步。
